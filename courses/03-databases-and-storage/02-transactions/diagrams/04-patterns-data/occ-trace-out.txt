== 1. optimistic check at READ COMMITTED
   A read version 0; B read version 0
   A: UPDATE ... WHERE version = 0 -> 1 row (not committed yet)
   B: same UPDATE issued; after 1.0 s it is still waiting: True
   A commits -> B returns after 1.01 s, rows updated = 0
   final row: ('A', 1)
== 2. optimistic check at REPEATABLE READ
   A read version 0; B read version 0
   A: UPDATE ... WHERE version = 0 -> 1 row (not committed yet)
   B: same UPDATE issued; after 1.0 s it is still waiting: True
   A commits -> B returns after 1.01 s with ERROR 40001 could not serialize access due to concurrent update
   final row: ('A', 1)
== 3. a 5 s edit while another request changes stock on the same row
   pessimistic: the stock update waited  4.817 s; the editor's save: saved
   optimistic : the stock update waited  0.011 s; the editor's save: conflict: 0 rows, show the user the new version
== 4. xmin as a version number
   after INSERT                       xmin = 236807
   after a no-op UPDATE (body = body) xmin = 236808
   after SELECT ... FOR UPDATE        xmin = 236808
   after two UPDATEs in one txn       xmin = 236810 (one transaction = one xmin)
   the same row copied to a new table xmin = 236811 (a dump/restore or logical copy renumbers it)
